# Mini Agent 项目开发总结

> 记录日期：2026-11-25  
> 当前快照：`Agent/mini-agent` 工作区  
> 对比基线：Git `HEAD`（`64b9aa8`，文档提交 `tool_system`）；最近一次 Agent 代码提交为 `998929d`（`Agent-Loop`）中的 `Agent/agent-loop/agent.ts`

## 一、本次阶段性结论

当前项目已经从上一阶段的“Agent 工具循环伪代码”推进为一个可以独立启动、连接真实模型并持续多轮对话的最小可运行版本（MVP）。

本阶段的核心成果不是实现了完整 Agent 工具系统，而是跑通了 Agent 的模型侧主链路：

- 用 TypeScript 建立可执行工程；
- 接入通义千问的 OpenAI 兼容接口；
- 在没有 API Key 时自动切换到本地模拟模型；
- 通过命令行持续读取用户输入；
- 维护多轮对话消息历史；
- 将模型回复以流式文本实时输出；
- 用模拟模型复现真实模型的流式响应结构，降低开发和调试对网络、额度的依赖。

目前代码仍属于“流式聊天 Agent 的基础骨架”，尚未迁移上一版中的工具调用、循环检测和最大轮数控制。

## 三、当前已实现功能

### 1. 可运行的 TypeScript 项目

项目使用以下核心依赖：

- `typescript`、`tsx`：TypeScript 编译与直接运行；
- `ai`：统一的模型调用、消息类型和流式接口；
- `@ai-sdk/openai`：通过 OpenAI 兼容协议访问模型；
- `dotenv`：加载本地环境变量；
- `@types/node`：Node.js 类型支持。

可用命令：

```bash
pnpm start
pnpm dev
```

其中 `pnpm start` 直接运行 `src/index.ts`，`pnpm dev` 使用 `tsx watch` 监听源码变化。

### 2. Qwen 真实模型接入

`src/index.ts` 创建了指向阿里云 DashScope 兼容接口的 OpenAI Provider：

```ts
const qwen = createOpenAI({
  baseURL: 'https://dashscope.aliyuncs.com/compatible-mode/v1',
  apiKey: process.env.DASHSCOPE_API_KEY,
})
```

存在 `DASHSCOPE_API_KEY` 时，使用 `qwen-plus-latest`；缺少密钥时则自动使用模拟模型。这个设计使项目既能调用真实模型，也能在没有密钥或网络不可用时继续调试交互与流式链路。

### 3. 持续的终端交互循环

程序使用 Node.js `readline` 持续收集输入：

1. 提示用户输入；
2. 忽略空输入；
3. 输入 `exit` 时关闭会话；
4. 将用户消息加入上下文；
5. 发起模型调用；
6. 流式输出回复；
7. 将完整回复加入上下文；
8. 再次调用 `ask()` 等待下一轮输入。

这已经形成最基本的“用户输入 → 模型生成 → 回复入历史 → 下一轮继续”的会话闭环。

### 4. 流式文本输出

模型调用使用 `streamText()`，通过 `for await` 读取 `result.textStream`：

```ts
for await (const chunk of result.textStream) {
  process.stdout.write(chunk)
  fullResponse += chunk
}
```

每收到一个文本块就立刻显示，同时把全部文本块拼接为完整回复，写回 `messages`。因此用户看到的是逐字/逐块输出，后续请求也能使用完整助手消息。

### 5. 多轮对话上下文

全局 `messages` 数组保存本次进程内的全部消息，每轮调用模型时作为 `messages` 参数传入。当前没有持久化，程序退出后会话历史会丢失。

系统提示词将 Agent 定义为“专注于软件开发的 AI 助手”，要求回答简洁、多用代码示例，并在问题不清楚时反问。

### 6. 无密钥 Mock Model

`src/mock-model.ts` 自行实现了一个满足当前调用方式的模型对象：

- 实现 `doGenerate()`，返回非流式文本结果；
- 实现 `doStream()`，返回与 AI SDK 兼容的流式事件；
- 将回复拆成 `text-start`、`text-delta`、`text-end`、`finish` 等事件；
- 用 `ReadableStream` 和定时器模拟每 30ms 输出一个字符；
- 返回模拟的 Token 用量；
- 根据整个 prompt 中的用户消息生成简单回复。

Mock Model 还能通过解析完整 prompt 演示“记忆”的来源：它并非自身保存了对话，而是因为代码每轮都把历史消息一起传给模型。当前可识别的示例包括问候、自我介绍、名字、代码相关问题和默认回复。

### 7. 更严格的 TypeScript 配置

`tsconfig.json` 启用了 `strict`、`noUncheckedIndexedAccess`、`exactOptionalPropertyTypes`、`verbatimModuleSyntax` 和 `moduleDetection: force` 等选项，并为 Node.js 环境配置了 `types: ["node"]`。编译器已确认当前源码可以通过 `--noEmit` 类型检查。

## 四、当前运行链路

```text
终端用户输入
    ↓
readline.question()
    ↓
将 user message 写入 messages
    ↓
streamText({ model, system, messages })
    ↓
遍历 result.textStream
    ↓
逐块输出到终端，同时拼接 fullResponse
    ↓
将 assistant message 写入 messages
    ↓
继续 ask() 等待下一轮
```

模型选择链路：

```text
存在 DASHSCOPE_API_KEY
    ├─ 是：DashScope Qwen
    └─ 否：createMockModel()
```

## 五、尚未实现或尚未迁移的能力

当前代码与完整 Agent 仍有明显距离，以下内容主要来自上一阶段设计或 `readme.md` 中的后续规划，目前不能视为已完成：

1. **工具系统**：没有工具定义、工具注册、`toolCalls` 解析和本地工具执行，也没有把工具结果作为 `tool` 消息送回模型。
2. **Agent Loop**：当前是聊天请求循环，不是严格的 `think → act → observe` 自主任务循环。
3. **循环保护**：上一版设计的工具名与参数指纹、重复结果检测、警告与熔断尚未迁移。
4. **轮数与预算控制**：没有 `MAX_TURNS`、Token 预算、90% 预警或递减回报停止机制。
5. **上下文治理**：消息会无限累积，尚未实现截断、时间衰减、LLM 摘要压缩或缓存优化。
6. **异常处理**：没有针对模型网络错误、超时、限流、响应中断和工具失败的完整恢复策略。
7. **输入流关闭处理**：批量管道测试中，首轮回复完成后 `readline` 已关闭，递归调用 `ask()` 会触发 `ERR_USE_AFTER_CLOSE`。正常人工输入 `exit` 的路径能主动结束，但 stdin 提前关闭的场景仍需补上 `'close'` 事件或状态判断。
8. **持久化与会话管理**：历史仅保存在内存，没有保存、恢复、清空和会话切换能力。
9. **可配置性**：模型名、Base URL、系统提示词和流式速度均硬编码在源码中。
10. **测试体系**：目前只有类型检查和手工运行，没有针对 Mock Model、上下文拼接和交互循环的自动化测试。

## 六、本次验证结果

1. 执行 `.\node_modules\.bin\tsc.cmd --noEmit`，退出码为 0，当前源码通过 TypeScript 类型检查。
2. 使用真实环境中的模型配置完成了一次流式调用，终端能实时显示 Qwen 回复。
3. 使用管道输入多行消息时，程序在首轮异步回复后遇到 `ERR_USE_AFTER_CLOSE`，说明当前实现适合普通交互式终端，但还不能安全处理 EOF/管道式输入。
4. 当前整个 `Agent/mini-agent` 目录在 Git 中仍是未跟踪状态；本次总结记录的是工作区现状，而不是已提交版本。

## 七、建议的下一步

下一阶段建议优先把“可运行聊天 MVP”升级为“可执行工具的最小 Agent”：

1. 定义至少一个真实工具，并接入 AI SDK 的工具调用流程；
2. 形成 `模型提出工具调用 → 本地执行 → 工具结果回传 → 模型继续回答` 的闭环；
3. 为工具执行增加白名单、超时、结果截断和异常捕获；
4. 恢复上一版的重复调用指纹与最大轮数保险丝；
5. 修复 stdin 关闭时的 `ERR_USE_AFTER_CLOSE`；
6. 为 Mock Model 和 Agent 循环补充自动化测试；
7. 再进入上下文压缩、Token 预算和多会话持久化。

## 八、本阶段一句话总结

本次实现完成了 Mini Agent 的模型接入与流式多轮对话骨架，并用 Mock Model 打通了无密钥开发路径；工具调用、自主循环和上下文治理仍属于下一阶段工作。
